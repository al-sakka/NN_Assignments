\section{Introduction}

Deep learning models need a lot of data to work well, but getting large labelled datasets
is often expensive or just not possible.  In this assignment we look at ways to boost model
performance when training data is limited.

For \textbf{Problems~1 and~2} we focus on \textbf{synthetic data generation} using the
ReducedMNIST dataset (10 digit classes, $28\times28$ images, only \textbf{350 training
samples per class}).  We train a \textbf{Conditional VAE (CVAE)} and a
\textbf{Conditional DCGAN (cDCGAN)}, use them to generate new images, filter those images
by how confident a classifier is about them, and then check whether adding them actually
helps classification.

% ==========================================
% 2. PROBLEM 1 — CVAE
% ==========================================
\section{Problem 1 --- Synthetic Data Generation with Conditional VAE}

\subsection{Methodology}

\subsubsection{Data Loading and Preparation}

The \textbf{ReducedMNIST} dataset has folders \texttt{0/} through \texttt{9/}, each
holding grayscale JPEG images of that digit.  Although the full training set contains
1\,000 images per class, we only use the \textbf{first 350 per class} on purpose to
simulate having limited data.  Every image is resized to $28 \times 28$ and normalised
to $[0, 1]$.

\subsubsection{Data Augmentation}
\label{sec:augmentation}

With only 350 images per class there is a real risk of poor test accuracy.  To help with this
we apply \textbf{15$\times$ data augmentation} through simple geometric transforms:

\begin{itemize}
    \item \textbf{Random rotation:} up to $\pm15^{\circ}$
    \item \textbf{Random translation:} up to 10\% horizontally and vertically
    \item \textbf{Random scaling:} between 90\% and 110\% of original size
\end{itemize}

These transforms keep each digit recognisable while adding variety similar to
real handwriting differences.  The training set grows from
$350 \times 10 = 3{,}500$ to roughly $5{,}600 \times 10 = 56{,}000$ samples.

\subsubsection{CVAE Architecture}

A VAE learns a smooth latent space that we can sample from to create new images.
By giving it the class label as an extra input, we get to choose \emph{which digit}
gets generated.

\begin{itemize}
    \item \textbf{Encoder:} The input image $(1, 28, 28)$ is concatenated with a learnable
          \emph{label map} --- a $28 \times 28$ embedding of the class label --- along the
          channel dimension, yielding a $(2, 28, 28)$ tensor.  Three convolutional layers
          (with BatchNorm and ReLU) downsample this to a 2\,048-dimensional feature vector,
          which is projected to the mean $\boldsymbol{\mu}$ and log-variance
          $\log \boldsymbol{\sigma}^{2}$ of a 64-dimensional latent Gaussian.

    \item \textbf{Reparameterization:} A latent code $\mathbf{z}$ is sampled via
          $\mathbf{z} = \boldsymbol{\mu} + \boldsymbol{\sigma} \odot \boldsymbol{\epsilon}$,
          $\boldsymbol{\epsilon} \sim \mathcal{N}(\mathbf{0}, \mathbf{I})$.

    \item \textbf{Decoder:} The latent code $\mathbf{z}$ is concatenated with a separate
          label embedding and projected back to $(128, 4, 4)$.  Three transposed-convolution
          layers upsample this to the reconstructed image $(1, 28, 28)$ with a final Sigmoid
          activation.
\end{itemize}

\subsubsection{Loss Function}

The CVAE is trained to minimise:
\[
    \mathcal{L}_{\text{CVAE}} = \underbrace{\text{BCE}(\hat{\mathbf{x}}, \mathbf{x})}_{\text{reconstruction}}
    \;+\; \underbrace{D_{\text{KL}}\!\bigl(\mathcal{N}(\boldsymbol{\mu}, \boldsymbol{\sigma}^{2})
    \;\|\; \mathcal{N}(\mathbf{0}, \mathbf{I})\bigr)}_{\text{regularisation}}
\]
The \textbf{BCE term} pushes the output to look like the input, while the \textbf{KL term}
keeps the latent distribution close to a standard normal so that we can smoothly
interpolate between digits and sample meaningful new ones.

\subsubsection{LeNet-5 Classifier}

We use LeNet-5 for two things:
\begin{enumerate}
    \item \textbf{Confidence filtering:} we first train it on the 350 real samples and use
          its softmax scores to judge how good each generated image looks.
    \item \textbf{Final evaluation:} we then retrain it from scratch on real + synthetic
          data and measure test accuracy.
\end{enumerate}

Architecture: Conv(1$\to$6, $5\!\times\!5$) $\to$ ReLU $\to$ MaxPool $\to$
Conv(6$\to$16, $5\!\times\!5$) $\to$ ReLU $\to$ MaxPool $\to$ FC(400$\to$120) $\to$
FC(120$\to$84) $\to$ FC(84$\to$10).  Trained for 20 epochs with Adam ($\text{lr} = 10^{-3}$).

\subsubsection{Generation and Filtering Pipeline}

\begin{enumerate}
    \item \textbf{Generate:} 5 independent runs $\times$ 1\,000 samples per class = 50\,000 total.
    \item \textbf{Score:} the pre-trained LeNet-5 computes the maximum softmax probability
          (confidence) for each generated image.
    \item \textbf{Filter into three datasets:}
    \begin{itemize}
        \item \textbf{Dataset A:} all 50\,000 generated samples (no filtering).
        \item \textbf{Dataset B:} only samples with confidence $\geq 0.9$ (high quality).
        \item \textbf{Dataset C:} samples with $0.6 \leq$ confidence $< 0.9$ (medium quality).
    \end{itemize}
    \item \textbf{Retrain:} for each dataset, combine the 350 real samples with the synthetic
          subset and retrain LeNet-5 from scratch.  Evaluate on the test set.
\end{enumerate}

Every synthetic dataset beats the 350-sample baseline of 95.90\%.

\textbf{Dataset~C} has more variety: slightly unusual stroke styles, borderline shapes, and
so on.  That extra diversity helps the classifier generalise, almost like a form of
regularisation.

The main takeaway here is that medium-confidence filtering works better than both no
filtering and strict high-confidence filtering, at least for VAE-generated data.

\section{Problem 2 --- Synthetic Data Generation with Conditional DCGAN}

\subsection{Methodology}

Everything from data loading to augmentation to the LeNet-5 pipeline stays the same as
in Problem~1.  The only difference is that we swap the CVAE for a
\textbf{Conditional Deep Convolutional GAN (cDCGAN)}.

\subsubsection{Generator Architecture}

\begin{enumerate}
    \item A 100-dimensional noise vector $\mathbf{z}$ is concatenated with a 10-dimensional
          label embedding.
    \item A fully connected layer projects the 110-dimensional input to $256 \times 7 \times 7$
          (with BatchNorm + ReLU).
    \item Two transposed convolution layers upsample to $128 \times 14 \times 14$ and then
          $64 \times 28 \times 28$.
    \item A final $3 \times 3$ convolution with Sigmoid produces the $(1, 28, 28)$ output.
\end{enumerate}

\subsubsection{Discriminator Architecture}

\begin{enumerate}
    \item The input image $(1, 28, 28)$ is concatenated with a label map $(1, 28, 28)$ along
          the channel dimension.
    \item Two convolutional layers (with LeakyReLU and Dropout) downsample to
          $128 \times 7 \times 7$.
    \item A fully connected layer outputs a single real/fake probability (Sigmoid).
\end{enumerate}

\subsubsection{Training Details}

\begin{itemize}
    \item \textbf{Loss:} Binary Cross-Entropy (BCE).
    \item \textbf{Label smoothing:} Real targets set to 0.9 instead of 1.0 to stabilise training.
    \item \textbf{Optimiser:} Adam with $\text{lr} = 2 \times 10^{-4}$, $\beta_{1} = 0.5$,
          $\beta_{2} = 0.999$ (standard DCGAN hyperparameters).
    \item \textbf{Epochs:} 100.
\end{itemize}

\section{Comprehensive Summary and Comparison with Assignment~2}

\subsection{Which GAN Selection Strategy Gives the Best Improvement?}

Out of the three filtering strategies, \textbf{Dataset~C} (medium confidence,
$0.6 \leq \text{conf} < 0.9$) gives the best GAN accuracy at \textbf{97.55\%},
just slightly above Datasets~A and~B (both 97.45\%).  For the CVAE the gap is
bigger --- Dataset~C hits \textbf{98.45\%}, the best number we saw anywhere.

Why does medium confidence win?  Those samples are different enough to teach the
classifier something new, but still look enough like real digits to be useful.
The high-confidence ones (Dataset~B) are basically copies of what the model
already knows, and the unfiltered set (Dataset~A) has some bad samples mixed in.

\subsection{Does Synthetic Data Reduce the Need for Real Data?}

Yes.  Starting from just \textbf{350 real images per class}, adding either VAE or
GAN samples pushes accuracy past the 350-real baseline (95.90\%) and even past
the \textbf{1\,000-real upper baseline} (97.25--97.60\%).  VAE Dataset~C gets to
98.45\%, which we probably could not reach even with 1\,000 real images.
So if collecting more real data is hard or expensive, generating synthetic
samples and filtering them carefully is a solid alternative.

\section{Problem 3 --- Understanding the Impact of Attention Mechanisms}

\subsection{Objective}

The goal is to compare a \textbf{baseline CNN} (LeNet-5) against the same network
augmented with a \textbf{spatial attention module} on two tasks:
\begin{enumerate}
    \item \textbf{ReducedMNIST} --- the same digit-image dataset from Problems~1 and~2.
    \item \textbf{Spoken Digits} --- classifying Mel-spectrogram images of spoken digits
          (the audio dataset from Assignment~2).
\end{enumerate}
We measure \emph{accuracy} and \emph{training time} for each configuration.

\subsection{Methodology}

\subsubsection{What Is Spatial Attention?}

A plain CNN applies the same convolution everywhere equally.
\textbf{Spatial attention} learns a 2-D mask (one value per spatial location) that
highlights the most informative regions --- for example, the stroke of a digit or
a strong harmonic in a spectrogram --- while fading out background clutter.

\begin{enumerate}
    \item \textbf{Channel pooling:} compute the average and max across the channel
          dimension, producing two single-channel maps.
    \item \textbf{Concatenation:} stack the two maps into a 2-channel tensor.
    \item \textbf{$3\times3$ convolution $\to$ 1-channel mask.}
    \item \textbf{Sigmoid:} normalise the mask to $[0, 1]$.
    \item \textbf{Element-wise multiply:} apply the mask to the original feature maps.
\end{enumerate}

The attention block is inserted \textbf{after the first pooling layer}, where the
spatial resolution is still large enough for the $3\times3$ kernel to capture local
saliency without blurring the whole map.

\subsubsection{Network Architectures}

\paragraph{ReducedMNIST --- LeNet-5.}
Conv($1 \to 6$, $5\!\times\!5$) $\to$ ReLU $\to$ MaxPool $\to$
\emph{[Spatial Attention]} $\to$
Conv($6 \to 16$, $5\!\times\!5$) $\to$ ReLU $\to$ MaxPool $\to$
FC(400$\to$120) $\to$ FC(120$\to$84) $\to$ FC(84$\to$10).

\paragraph{Spoken Digits --- SpectrogramCNN (from Assignment~2 Q3).}
For the spectrogram task we reuse the \textbf{exact 3-layer CNN from Assignment~2 Q3}
(Conv--BN--ReLU--Pool $\times 3$, with Dropout in the FC layers).
This is important because the assignment explicitly asks to \emph{revisit the spoken
digits task from Assignment~2}, so LeNet-5 would not be the right baseline.
Spatial attention is inserted after the first pool layer ($16 \times 16$ maps).

\subsection{Analysis}

\begin{enumerate}
    \item \textbf{Model architecture matters more than attention.}
          Switching from LeNet-5 to SpectrogramCNN or ResNet-18 has a far bigger
          impact than adding any attention module.  ResNet-18 + SE matches the
          SpectrogramCNN baseline at 97.67\% on spoken digits while also topping
          the MNIST leaderboard at 98.40\%.

    \item \textbf{Spatial attention helps on MNIST but hurts on spectrograms.}
          On clean, centred digit images the attention mask learns to focus on
          the stroke.  On spectrograms, the discriminative information is spread
          across \emph{frequency bands} (channels), not spatial locations ---
          so spatial attention is the wrong inductive bias.

    \item \textbf{Self-attention is data-hungry.}
          The Transformer-style head (95.90\% on MNIST, 64.00\% on audio)
          underfits on these small datasets.  It needs more data or aggressive
          augmentation to shine.

    \item \textbf{SE (channel) attention on a shallow backbone underperforms.}
          LeNet-5 only has 6 and 16 channels, so there is not much for the
          SE block to re-weight.  On ResNet-18 (64--512 channels), channel
          attention becomes effective again.

    \item \textbf{Training-time overhead is small.}
          Spatial attention adds about 7\% wall-clock time on LeNet-5.
          The self-attention head is the most expensive at $+34\%$ due to the
          matrix multiplications in the Transformer layer.
\end{enumerate}

\subsection{Comparison with Assignment~2}

In Assignment~2, the SpectrogramCNN baseline for spoken digits achieved
$\sim$99\% accuracy on a clean train/test split.  Here we see 97.67\% instead,
which is slightly lower because we use a smaller data subset and a fixed seed.
The key takeaway remains the same: \textbf{model architecture} (deeper CNNs with
BatchNorm and Dropout) matters far more than bolting on attention when the task
is already well-suited to convolutions.

\subsection{Objective}

Build a complete \textbf{Arabic question-answering pipeline} that demonstrates
three levels of retrieval:
\begin{enumerate}
    \item \textbf{Classical search} (TF-IDF).
    \item \textbf{Semantic search} (dense embeddings + FAISS).
    \item \textbf{Retrieval-Augmented Generation (RAG)} --- a small LLM answers

\end{enumerate}
We compare all three against a baseline of \textbf{LLM-only generation}
(no retrieval) over 10 Arabic questions about a selected book.

\subsection{Qualitative Analysis: RAG vs.\ LLM-Only}

For each of the 10 questions, we compared the RAG answer (with top-5 retrieved
context) against the LLM-only answer (no retrieval).  Key observations:

\begin{enumerate}
    \item \textbf{RAG answers are more grounded.}
          The RAG model cites specific concepts from the Muqaddimah (e.g.,
          ``\emph{al-umran}'' as the study of human society, the role of
          \emph{asabiyyah} in state formation).  The LLM-only model invents
          plausible-sounding but often \emph{factually wrong} details --- for
          example, listing ``physics'' as one of Ibn Khaldun's divisions of
          knowledge, or giving incorrect birth dates.

    \item \textbf{LLM-only hallucinations are severe for a 1.5\,B model.}
          Without retrieval, the model produced Chinese characters mid-sentence,
          attributed incorrect books to Ibn Khaldun (e.g., ``al-Tabaqat''),
          and gave wildly wrong dates (965--1029 instead of 1332--1406).
          RAG eliminates most of these errors by anchoring the answer in
          real text.

    \item \textbf{RAG struggles with hard comparative questions.}
          For Q5 (organic vs.\ military kingship) and Q10 (five stages of the
          state), the retrieved passages did not contain a clean, direct answer,
          so the RAG model's output was rambling and repetitive.  This is a
          retrieval quality problem, not a generation problem.

    \item \textbf{Both modes produce fluent Arabic.}
          The Qwen model handles Arabic well overall.  The main quality
          difference is \emph{factual accuracy}, not language fluency.
\end{enumerate}

\subsection{TF-IDF vs.\ Semantic Search: Detailed Comparison}

\begin{itemize}
    \item \textbf{TF-IDF} matches \emph{exact surface words}.  It does well when
          the query contains distinctive keywords (Q8, ``\arb{المقدمة}'', scored 0.47),
          but fails when the answer uses synonyms or paraphrases.

    \item \textbf{Semantic search} matches \emph{meaning}.  Its top-1 scores are
          consistently $\geq 0.85$, even for indirect questions like Q3
          (``climate and morals'') where TF-IDF scores only 0.18.

    \item The semantic retriever uses \texttt{multilingual-e5-small}
          (384-dimensional embeddings), which is fast to encode ($\sim$23\,s for
          10\,946 passages on GPU) and produces normalised vectors suitable
          for exact inner-product search via FAISS.
\end{itemize}

\subsection{Summary and Key Takeaways}

\begin{enumerate}
    \item \textbf{Semantic retrieval dominates classical retrieval for Arabic.}
          A mean top-1 score of 0.88 vs.\ 0.28 --- the dense embeddings
          capture meaning far better than TF-IDF on morphologically rich Arabic.

    \item \textbf{RAG dramatically reduces hallucination.}
          For a small 1.5\,B-parameter model, retrieval is not optional ---
          it is essential.  Without it, the model fabricates facts, mixes
          languages, and gives wrong dates.

    \item \textbf{Retrieval quality is the bottleneck.}
          When the FAISS index returns the right passages, the LLM generates
          good answers.  When it does not (hard comparative questions), the
          LLM struggles regardless.  Future work should focus on better
          chunking, hybrid retrieval (TF-IDF + dense), and re-ranking.

    \item \textbf{Arabic NLP needs more attention.}
          OCR artefacts in the source text (the Internet Archive scan has
          character-level noise) hurt both retrieval and generation.
          Cleaner corpora and Arabic-native embedding models would help.
\end{enumerate}
